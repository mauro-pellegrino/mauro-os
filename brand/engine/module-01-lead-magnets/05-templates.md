# The Templates

Everything that surrounds the magnet. The asset is only half of it, and this is the half most people improvise.

Copy these directly. Swap the brackets. They're the exact structures behind the numbers on page 03.

---

## The X post

```
[Hook line: one sentence]

[Setup: 1-2 sentences. What you built plus a credibility specifier.]

Inside the [file / guide / breakdown]:

- [Specific thing they receive]
- [Specific thing they receive]
- [Specific thing they receive]
- [optional 4th]
- [optional 5th]

Want a copy? Like + Comment "[KEYWORD]" and I'll send it over ASAP

(Must be following)
```

**Rules that came from testing, not taste:**

- Bullets use a dash, never a checkmark.
- Keyword in quotes, all caps, no punctuation around the quotes.
- Always "Like + Comment", never just "Comment". The single action tested worse.
- Close with `(Must be following)` on its own line.
- 120 to 160 words. Shorter usually wins.

**The bullets are the entire sell.** Each one names a deliverable, not a topic. "The split you're aiming for" beats "how to think about your funnel." If a bullet could appear in someone else's post about the same topic, rewrite it.

### Hook formulas

| Formula | Use when |
|---|---|
| "[Tool] is INSANE for [task]" | A specific tool is having a moment. Highest performer on prompt files |
| "[Tool] is CRAZY good" | Same, shorter, when the tool name does the work |
| "[Problem statement], and that's killing your [outcome]" | Pain-led, when no tool is the hook |

Tool-led hooks work when the tool is genuinely trending and fade when it isn't. Reusing the formula months after the tool peaked underperforms even with identical structure.

## The LinkedIn post

Different structure. Do not reuse the X post here.

```
[Hook line: one sentence, outcome-led or contrarian]

[Setup: 2-3 sentences. Explanation, authority anchor, what you built.]

[Optional aside: "(This is the exact system I run daily)"]

I break down:

✓ [Specific thing]
✓ [Specific thing]
✓ [Specific thing]
✓ [optional 4th]

Here's how to get it:

1. Connect with me [YOUR FULL NAME]
2. Comment "[KEYWORD]" below

I'll send it over ASAP.
```

**Rules:**

- Bullets use ✓ here, not a dash.
- Two-step CTA: connect, then comment. Your name must match your profile exactly so it links.
- No `(Must be following)` on LinkedIn.
- 180 to 220 words. Longer than X because LinkedIn rewards depth.
- Authority anchor goes in the first two paragraphs. Always. Pull it from `brand-context.md`.

### Hook formulas

| Formula | Note |
|---|---|
| "I [achieved outcome with specifics]" | Consistently the highest impressions. Verified numbers only |
| "[Topic] is the 80/20 of [thing]" | Good when one lever genuinely dominates |
| "You need to [contrarian action]" | Works when you can defend it in paragraph two |
| "[Thing] requires a NEW playbook" | Good for a shift you can evidence |

## The DM

Fires when someone comments the keyword.

```
Hey (name), here's the [file / guide / breakdown]:

[LINK]

Page [N] is the one to start on. [One line on why that page matters most.]
```

**That last line is the whole thing.** It's the difference between a download and a read. A DM that hands over a link and stops has ended the conversation at the exact moment it could have started.

### Optional addition, only when a real adjacent asset exists

```
BTW, want me to send over [the adjacent thing] as well? Let me know.
```

One line, low friction, easy yes or no. The adjacent thing must actually exist and be ready to send. Skip it entirely if it doesn't. Offering something you can't deliver costs more than the extra reply is worth.

### The noun matters

| Subtype | Noun |
|---|---|
| Prompt or swipe file | file |
| Framework | breakdown |
| Case study | breakdown |
| A video | breakdown, **never** "video" |
| Niche-specific kit | guide |

If the asset is a video, nothing in the post, the image or the DM reveals that. The reader should feel they're getting a written deep-dive. The video then over-delivers when they click.

## Auto-DM configuration

Whatever tool you use, these are the settings that matter.

| Setting | Value | Why |
|---|---|---|
| Trigger keyword | Magnet-specific, all caps, 3-7 chars | Short enough to type wrong-free |
| Auto-connect | **OFF** | Verified live setting. Do not turn it on |
| Partially engage | **ON** | Catches likes without comments |
| Follow-up DM | **OFF** | The follow-up costs more goodwill than it earns |

## The cover image

**Default: screenshot the asset's own first screen.** Not a designed card.

- Notion: the parent page, showing the title, the intro and the list of nested subpages
- A deck: slide one
- A doc: page one

**Why.** It shows the reader the actual thing they're about to receive, and the visible subpage list does the "what's inside" job for free. A designed card promises. A screenshot proves. It's also faster, because the asset already exists by the time you need the cover.

**What makes one work:**

- Crop tight. No browser chrome, no sidebar, no cursor
- Title legible at feed thumbnail size. If it isn't, zoom the page before capturing
- Enough of the subpage list visible that they can count the pages
- No internal UI. No comment bubbles, no share button, no avatars
- Capture at 2x, then downscale. A 1x screenshot looks soft in feed

**Skipping the cover makes the post perform noticeably worse.** Every time.

### Fallback: the designed card

Only when no asset exists yet, or its first screen is text-heavy and dull.

- Colour band header in your brand colour
- Dark body, near-black, white text
- Title large, one or two line subtitle
- 4 to 6 bullets showing what's inside
- Your handle as a credit line

Build it as HTML and screenshot it. Don't generate it with an image model, the title and bullets have to be exactly right.

## The page structure

```
PARENT PAGE
  Cover: solid [your brand colour]
  Authority line
  Title
  Subtitle (number anchor + proof anchor)
  Intro, 1-2 lines
  → the nested subpages appear here
  CTA
  "Created by [your handle]"

  SUBPAGE 1 ... N-2   the content
  SUBPAGE N-1         THE FILL-IN PAGE
  SUBPAGE N           the CTA
```

5 to 7 subpages. The second to last is always the fill-in page. The last is always the CTA. Non-negotiable, and it's the rule most builds break.

## In-asset prompt blocks

Every page carries two, so the visuals never depend on inventing prompts later.

```
> PAGE IMAGE PROMPT (16:9, [real screenshot / worked example / doodle]):
> [what to show, what it teaches, what text if any]

> HTML STYLE PROMPT:
> [layout, the one thing that carries the page, colour usage]
```

**One rule that isn't obvious.** On the page whose whole job IS the asset (the prompt list, the template), a "real example screenshot" would just restate the text, which is banned. Point that page's image at the asset's *output* instead. Show the prompt working, not the prompt.
